# MarkVal API - AI Agent Skill Guide

This document is a guide for AI agents to interact with the **MarkVal PDF Verification API**. This skill is invoked when a user wants to verify, compare, or reconcile numerical values or constants in a calculation PDF (File A) against source evidence PDFs (File B).

---

## 1. Setup and Base URL

The MarkVal API is assumed to be running on an external server. You must update the Base URL below to match your actual deployment environment:

- **Base URL:** `http://<YOUR_MARKVAL_API_HOST>:<PORT>` (e.g., `http://192.168.1.100:8000`)
- **Interactive OpenAPI Docs:** `http://<YOUR_MARKVAL_API_HOST>:<PORT>/docs` or `/openapi.json`
- **Authentication:** Currently, no authentication header is required.

---

## 2. Core Workflow for AI Agents

To perform a complete PDF verification task, follow this sequential workflow:

```mermaid
graph TD
    A[Start: Upload File A] -->|POST /api/v1/sessions| B(Get session_id & CheckItems)
    C[Upload File B] -->|POST /api/v1/source-documents| D(Get document_id & SourceItems)
    B --> E[Run Matching]
    D --> E
    E -->|POST /api/v1/match| F(Review MatchResults)
    F -->|PATCH /api/v1/results/{id}| G[Approve/Reject Results]
    G -->|POST /api/v1/sessions/{id}/export| H[Export Annotated PDF]
```

### Step 1: Upload Calculation Sheet (File A)
Upload the target calculation sheet PDF to initiate a matching session.
- **Endpoint:** `POST /api/v1/sessions`
- **Content-Type:** `multipart/form-data`
- **Parameters:**
  - `file`: (File, Required) The PDF calculation sheet.
  - `prompt_template_id`: (String, Optional) UUID of a custom extraction prompt template.
  - `categories`: (String, Optional) A comma-separated list of categories to filter extracted items (e.g., `"固定荷重,積載荷重"`). Filtering by categories is highly recommended to reduce token consumption and improve matching accuracy.
- **Key Response Data:**
  - `id`: The generated `session_id` (UUID). Use this in subsequent matching steps.

### Step 2: Upload Source Document (File B)
Upload the reference source document (File B).
- **Endpoint:** `POST /api/v1/source-documents`
- **Content-Type:** `multipart/form-data`
- **Parameters:**
  - `file`: (File, Required) The reference PDF document.
  - `title`: (String, Optional) Custom title for the source document.
  - `version`: (String, Optional) Version tag (e.g., `"v1.0"`).
  - `categories`: (String, Optional) Comma-separated list of categories.
- **Key Response Data:**
  - `id`: The generated `document_id` (UUID).
- **Agent Note (SHA-256 Duplication Check):**
  - If the same file is uploaded, the API will return a `409 Conflict` status code containing the existing document ID. In this case, reuse the existing ID instead of trying to re-upload.

### Step 3: Execute Collation (Match)
Execute matching between the extracted items of File A and File B.
- **Endpoint:** `POST /api/v1/match`
- **Content-Type:** `application/json`
- **Payload:**
  ```json
  {
    "session_id": "YOUR_SESSION_ID",
    "document_ids": ["YOUR_DOCUMENT_ID"]
  }
  ```
  *(Note: Providing specific `document_ids` is recommended. If omitted, matching runs against all registered source documents.)*
- **Key Response Data:**
  - A list of matched results, each containing:
    - `id`: The match result ID.
    - `check_item_label` & `check_item_value`: The value extracted from File A.
    - `matched`: Boolean indicating if the value was successfully matched.
    - `confidence`: Confidence score (0.0 to 1.0).
    - `status`: Result status (initially `"approved"`, `"rejected"`, or `"pending"`).
    - `ai_reasoning`: The explanation/justification generated by the AI for the match.
    - `source_item`: Information about the matched item in File B.

### Step 4: Review and Update Status (Optional)
If manual review or correction is required, update the status of individual match results.
- **Endpoint:** `PATCH /api/v1/results/{result_id}`
- **Payload:**
  ```json
  {
    "status": "approved" 
  }
  ```
  *(Allowed values: `"approved"`, `"rejected"`, `"pending"`)*

### Step 5: Export Annotated PDF
Generate and download the final PDF report with verification marks (checkmarks ✓) drawn onto File A.
- **Endpoint:** `POST /api/v1/sessions/{session_id}/export`
- **Response:** PDF file binary (`application/pdf`).

## 3. Prompt Template Management

You can manage prompt templates to fine-tune how check items are extracted from File A.

- **List Templates:** `GET /api/v1/prompt-templates`
- **Create Template:** `POST /api/v1/prompt-templates`
  ```json
  {
    "name": "Structure Calculations Default",
    "content": "Instructions to target specific values...",
    "industry": "Structural Engineering"
  }
  ```
- **Update Template:** `PUT /api/v1/prompt-templates/{template_id}`
- **Delete Template:** `DELETE /api/v1/prompt-templates/{template_id}`

---

## 4. Tips for AI Agent Optimization

- **Category Filtering (Token & Accuracy Booster):**
  When uploading File A or File B, always try to supply the `categories` parameter if you have metadata or user intent about the calculation scope. This restricts the matching search space and prevents token bloat.
- **Handling API Concurrency Limitations:**
  The server enforces concurrency limits on Yomitoku OCR and LLM calls via internal semaphores. Do not send multiple huge sessions concurrently to prevent timeouts.
- **Caching Mechanism:**
  Duplicate source documents are automatically blocked by the SHA-256 hash check. Always handle `409 Conflict` by parsing the JSON response and extracting the existing `id`.
